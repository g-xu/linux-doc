# 物理组织与初始化：写前约定

目标是解释普通 RAM 如何从范围记录变成运行期分配器资源，不重写 Buddy 算法。技术基线与操作边界见[本轮队列](completion-mm-series.md)。

| 问题 | 应能完成的判断 |
| --- | --- |
| Q0 | 区分物理地址、PFN、页数据、struct page、vmemmap、Node/Zone 和 section，不依赖名称互相定义。 |
| Q1 | 用 memory=[0,16)、[24,32)，reserved=[2,4)、[26,27) 推演范围差集，区分空洞与保留。 |
| Q2 | 同一范围中早期申请两页，推演选址、保留更新、21→19及下一次候选；解释物理/虚拟返回和方向/节点条件。 |
| Q3 | 区分 spanned/present/managed/free，判断有描述符、NOMAP、字节边缘和可交付资格不能混用。 |
| Q4 | 解释 arm64 接受/裁剪/保留、sparse_init、Zone 初始化与 mem_init 移交的因果，不把所有保留固定为同一阶段。 |
| Q5 | 推演常规页引用初值、保留标记、managed 增加与 Buddy 加入；区分延后初始化和检测接管。 |
| Q6 | 判断 memblock 内部 API 的用途、生命周期、成功失败、回退和保留释放边界；不写运行期驱动乱加 RAM 例子。 |
| Q7 | 解释元数据自身占用、初始化失败、热插拔/设备页的非普通路径，能找到目标源码。 |

图计划：资源与描述关系、同一范围早期分配前后、初始化交接状态。数字用于模型，页大小和真实参数不固定。先说明概念，再进入字段、计数和源码。

独立审阅按最多三轮协议，原问题与整篇判断共同计数；只推进当前篇，结果写入本篇审阅记录并更新队列。
