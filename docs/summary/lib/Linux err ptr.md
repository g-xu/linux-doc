## err ptr
在Linux内核中，函数通常返回指针。为了避免修改函数签名以同时返回“结果指针”和“错误码”（例如通过 `int *err` 参数），内核使用了一种巧妙的机制：**利用虚拟地址空间的最后 4KB（`0xFFFFF000` ~ `0xFFFFFFFF`，即 `-4095` 到 `-1`）来存储错误码。**

因为有效的内核指针永远不会指向这个区域（这是保留区），所以如果一个指针的值落在这个范围内，它就被视为一个错误码，而不是一个有效地址。

### 1. Linux 内核 ERR_PTR 相关 API 汇总

主要头文件：`&lt;linux/err.h&gt;`

| API 接口 | 参数示例 | 返回值 | 功能描述 | 典型使用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **`ERR_PTR(err)`** | `long err = -EINVAL` | `void *` | 将整数错误码（如 `-ENOMEM`）转换为指针类型。 | 在返回指针的函数中，遇到错误时返回错误码。 |
| **`PTR_ERR(ptr)`** | `void *ptr` | `long` | 将错误指针还原为整数错误码。 | 调用者发现返回的是错误指针后，提取具体的错误码（如 `-EBUSY`）。 |
| **`IS_ERR(ptr)`** | `const void *ptr` | `bool` (long) | 检查指针是否指向“错误区域”。<br>**注意：** `NULL` 不算错误。 | 判断函数返回值是否包含错误码。**不包含 NULL 检查**。 |
| **`IS_ERR_OR_NULL(ptr)`** | `const void *ptr` | `bool` | 检查指针是 **错误指针** 或者 **NULL**。 | 用于那些既可能返回错误，也可能返回 NULL（表示无对象）的接口。 |
| **`PTR_ERR_OR_ZERO(ptr)`** | `const void *ptr` | `int` | 如果 `ptr` 是错误指针，返回错误码；<br>如果 `ptr` 是有效指针或 NULL，返回 0。 | 用于将指针函数的返回值直接转换为 `int` 类型的函数返回值。 |
| **`ERR_CAST(ptr)`** | `const void *ptr` | `void *` | 将一个错误指针类型转换为另一个指针类型。 | 避免编译器警告（const 转换或类型转换），本质上就是透传错误指针。 |
| **`IS_ERR_VALUE(val)`** | `unsigned long val` | `bool` | 低级宏，检查一个整数值是否落在错误范围内。 | 通常用于汇编或极其底层的检查，驱动开发较少直接使用。 |

---

### 2. 关键注意事项 (必读)

1.  **`IS_ERR(NULL)` 是 false**：
    *   这是最容易犯错的地方。`IS_ERR` 只检查指针是否在 `-1` 到 `-4095` 范围内。`NULL` (0) 显然不在此范围。
    *   如果你的函数返回 `NULL` 表示“没找到”，返回 `ERR_PTR` 表示“出错”，调用者必须分别处理。

2.  **`PTR_ERR` 的使用前提**：
    *   只有当你确定 `IS_ERR(ptr)` 为 true 时，使用 `PTR_ERR(ptr)` 才有意义。
    *   虽然对普通指针调用 `PTR_ERR` 只是简单地把地址转为 long，但在逻辑上是错误的。

3.  **地址映射原理**：
    *   为什么是 `-4095` (0xFFFFF001)？因为内核页大小通常是 4KB (4096字节)。
    *   任何有效的对象都不可能从地址空间的最后一个 Page 开始，因为那样它会立即溢出地址空间。所以内核开发者拿这一页专门用来放错误码。
