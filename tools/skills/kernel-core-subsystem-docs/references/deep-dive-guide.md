# 深入：按问题展开机制，不按模板批量填篇

## 选择边界和文件

先说清本专题的任务、主要输入输出、拥有的状态及与外部的交接点，再选择阅读入口。

专题应有可解释的职责边界，不要求是一整个目录或独立文件。共享基础设施可被多个专题使用；不要将语义不同的工作仅因“都很小”而强行合并，也不要只因体量大就拆开一条完整机制。

优先让一篇 `sub/<专题>/00-overview.md` 讲完整的小专题。只有当内容分别服务于查接口、读实现、理解策略或诊断时才拆篇。拆分后保留简短背景与实际阅读链接，而不是让读者逐篇跳转才能理解一个句子。

| 文章 | 主要问题 |
| --- | --- |
| `00-overview.md` | 本专题在全局中负责什么，核心机制是什么，如何入手 |
| `01-api.md` | 谁可以调用什么接口，参数、返回、所有权和上下文契约是什么 |
| `02-internals.md` | 状态怎么保存，一条操作如何执行、失败如何收尾 |
| `03-algorithm.md` | 为什么这样选择或组织，哪些不变量决定行为 |
| `04-debug.md` | 如何从症状找到状态、路径和观测点 |

用户只要一个算法或一条路径时，将其作为本次专题的主线，不强行补齐其余文件。

## API 与使用契约

分开用户态 ABI、其他子系统可调用接口、内部回调与私有辅助函数。头文件声明、导出符号和 UAPI 的作用不同，不把出现过的函数全称为“公共 API”。

以典型用法组织接口表，按需要补参数含义、错误返回、睡眠 / 中断限制、引用获取与释放。需要签名时保留正确类型，不为了固定表格牺牲关键类型语义。

示例标明来自哪个真实调用者，或明确写“教学伪代码”。示例未编译 / 未运行就说明，不将阅读源码的结果写成实验结论。

## 数据与实现路径

围绕主要操作解释对象关系和必要字段，尤其说明对象与引用生命周期、队列成员资格、状态标志和资源释放时机。

典型路径按“入口条件 → 核心判断 → 状态修改 → 交接 / 返回”展开。除了顺利完成，还解释实际存在的失败、撤销、重试、慢路径或销毁中的一种，避免只描述 happy path。

遇到回调、宏、静态内联或条件编译，追到实际实现及调用者；索引图和 grep 命中只提供候选，不能直接代替执行顺序证据。

保留少量源代码和伪代码，不整段复制大函数。源码锚点写成“源码相对路径 + 符号 + 必要行号”，避免只有会漂移的行号。

## 算法与策略

先用具体输入演示，再解释数据结构、决策依据和维护不变量。读者应能自己算一轮结果，而不只是背公式或调用链。

涉及复杂度时明确变量和统计范围，例如候选任务数、队列长度或节点数。整体操作成本不等于某个树操作的成本；不要把渐进复杂度写成实时延迟保证。

性能与退化按“条件 → 行为变化 → 观测方法”解释。区分直接由代码可推导的结果和必须实验验证的结果，避免无依据的性能倍数。

调参只列本专题相关项，写清目标版本中的定义、默认值和触发机制。历史算法、新版本特性和目标版本的当前实现分别描述，不能混成同一条路径。

## 生命周期、交互和并发专篇

全局关系密集时可拆到父级手册，不强制每个子系统都写以下三篇。

| 视角 | 应说清的内容 | 易错点 |
| --- | --- | --- |
| 生命周期 | 状态判据、触发事件、执行者、所有权交接及失败回退 | 把彼此独立的条件或标志硬排成单线状态机 |
| 模块协作 | 关键调用、回调、共享状态、异步交接及其契约 | 把同文件关系说成没有关系，或把无搜索命中说成不存在依赖 |
| 并发约束 | 共享数据、保护手段、锁序、执行上下文及无锁保证 | 把字段名相似、都是 per-CPU 或都出现 RCU 当成同一同步协议 |

交互用少量关键边、分组图或关系表表达即可。若用户需要完整矩阵，分别标记“已确认关系”“范围内未发现”“未核对”；完整性必须与搜索范围匹配。

并发说明应落到实际声明和使用点：什么保护读写，引用计数是否只管存活，RCU 是否只管读侧与延迟回收，锁间顺序是源码约束还是推断。给反例时依据实际可达路径，不伪造 lockdep 输出。

涉及 PREEMPT_RT 时，在相关路径解释锁类型、上下文或调度行为的差异；不要要求所有文章复制一遍 RT 章节，也不能从一种锁推广到全部锁。

## 可观测性

挑选能解释用户问题的 tracepoint、计数器、调试接口或测试。说明事件记录在机制的哪个阶段，字段是什么单位、什么范围，需要什么配置。

命令先给只读检查；调参、故障注入、压力实验需写清前提和风险，生成文档不等于允许执行。没有可用机器时仅给复现方案，标注“未运行”。

## 更新父级文档

专题完成后将父级阅读地图改成实际文档链接，并补充新增契约和证据。
只更新受影响的状态和事实，不重新生成整个目录，不抹掉旧文或用户编辑。出现基线冲突时先指出，不能把两版内容自动拼接成“新版本”。
