# 总览：先建立可用的心智模型

总览是一篇完整的学习文章，不是文件索引或缩写词表。读者应能复述模块如何工作，并知道下一步该读什么。以下是内容检查点，不要求照抄标题或凑固定节数。

## 1. 从一个具体问题开始

选一个读者熟悉的现象或请求：为什么可运行任务仍需等待、为什么地址看似有效却触发缺页、为什么同一个文件可以通过多种文件系统访问。

先回答：模块对谁提供什么能力、管理什么资源、承担哪些约束，以及不负责什么。用一句核心直觉压缩全貌，再用正文展开；不能套用到其他模块的独特性比“重要且复杂”更有用。

在开头简短注明源码版本、目标架构、补丁及未知配置，详细基线放在 `99-evidence.md`。

## 2. 展示职责和协作地图

按实际职责组织模块，而非复制源码目录。读者应看出策略层、执行机制、状态存储和观测接口之间的分工，不强行将所有子系统套成同一种分层。

可以用一张简洁示意图和一张表：

| 职责或专题 | 解决的问题 | 关键输入 / 输出 | 源码入口 |
| --- | --- | --- | --- |

图中的边要说明是直接调用、回调、共享状态还是异步通知。只画已追踪的关键关系；省略的关系不等于不存在。规模大时先画主路径或分组图，不绘制无法阅读的全量网格。

记录函数族、回调实例和相关文件，而不是将一个专题绑定到某段连续行号。例如同一文件里的选择策略与跨 CPU 迁移逻辑可能交错，不宜靠行号截断职责。

不同目标需要不同切口，以下只用于选题，不是固定模块划分：

| 目标 | 优先回答的问题 | 不要混成一个概念 |
| --- | --- | --- |
| mm | 物理页怎样分配，虚拟地址怎样映射，压力下怎样回收 | page / folio 的资源状态与 mm / VMA / 页表的地址空间状态 |
| sched | 任务为何等待，策略怎样选任务，机制怎样切换，多核怎样协作 | 任务状态、队列成员资格、当前运行任务，以及请求重新调度与实际切换 |
| VFS / 文件系统 | 统一文件接口怎样落到具体实现，路径查找、打开、缓存和写回怎样衔接 | VFS 契约与具体文件系统实现；inode、dentry、file 及缓存的不同生命周期 |
| cgroup / namespace | 任务如何归属和迁移，资源如何控制，哪些状态被隔离 | 资源控制与命名 / 可见性隔离；不同控制器或 namespace 的各自边界 |

优先跟踪用户关心的操作，不试图让一个对象生命周期代表整个复杂子系统。

## 3. 用少量对象串起来

只解释主路径绕不过的对象：它代表什么，谁创建和持有，关键字段编码了什么状态，以及谁有权修改。

将两个容易混淆的概念放在一起解释，例如任务状态与是否在队列、虚拟地址范围与实际物理页、对象引用与对象锁。需要时补充对象之间的一对多、嵌入、引用或缓存关系。

字段表只保留理解流程需要的字段。不要一开始倾倒完整结构体，详细字段和同步规则可放到后续专题。

## 4. 跟着一个请求走一遍

从真实入口开始，按运行顺序追踪“检查什么 → 选择谁 → 修改什么状态 → 谁接手 → 如何完成”。关键步骤附源码函数和输入输出变化；代码只截取解释所需的片段，删节和伪代码明确标记。

至少讲清一条正常路径，另选一个代表性的异常或慢路径：竞争、资源不足、回退、异步完成、取消或重试。不是所有模块都存在相同异常，不为套模板虚构路径。

解释快速路径为何能快、慢路径在补救什么。模块间交接要指出数据或所有权变化，不能把不同分支串成现实中不会发生的“总调用链”。

让算法有直觉：用一个小输入演示选择、拆分、合并或记账如何改变结果，并说明关键约束。不要求初学者先阅读完整内部实现。

## 5. 按问题提供进阶入口

阅读地图至少覆盖本文识别出的主要职责，使用以下信息：

| 想弄清的问题 | 专题状态和文档入口 | 源码阅读起点 |
| --- | --- | --- |

- 已展开：链接实际存在的文章，并简短说明能读到什么。
- 未展开：只写专题名称、状态和源码入口，不能创建空篇假装覆盖，也不能写不存在的 Markdown 链接。
- 正在补写：说明具体缺口，不使用没有范围的“完成”标签。

同一份地图可安排“第一次读”“深入机制”“查接口 / 排障”的路径。每条路径都应有实际内容，不能只是重复目录树。

不要同时将“文章已存在”和“建议未来写作”混在一个无状态的链接列表中。

## 交付前自问

1. 只读这一篇，能解释模块在解决什么、为什么这样拆分、请求如何走完吗？
2. 图、对象、流程和进阶地图是否使用一致的术语、边界与基线？
3. 是否有用“见其他篇”代替本篇必须讲清的背景，或者链接到还不存在的文件？
4. 是否让函数名淹没概念，或让类比掩盖真实状态与配置条件？

总览已完成不代表所有专题已完成。提交总览时允许进阶地图存在明确的“未展开”项。
