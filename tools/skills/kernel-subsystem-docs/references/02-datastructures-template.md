# 02-datastructures.md 模板

> 质量基准：`output/i2c/02-datastructures.md`（571 行）

## §1.0 先分清 N 组关系（开篇必写）

至少 ≥2 组关系，每组三步：
1. 先否掉错误类比（"X 不是 Y"）
2. 对比表逐行摊开：是不是 struct device / 注册到哪条总线 / 会不会绑 driver
3. "为什么不会发生"找到代码依据——否定性论断同样给行号

★ **固定条目：本子系统有几层可插拔？** 一行一层，列 = 层名 / ops 结构体 / 实现者住在哪些目录 / 实现数。
这条最容易被"只有一层"的直觉盖过去：

| 子系统 | 层数 | 各层的 ops |
|---|---|---|
| i2c / spi | 1 层 | `i2c_algorithm` / `spi_controller` 的回调 |
| ★ virtio | **2 层** | 传输层 `virtio_config_ops`（9 个实现，5 个目录） + 设备驱动 `virtio_driver`（25 个文件 / 22 个叶子目录） |

搞错层数的后果很具体：把两层画成一层，"谁调用谁"的方向就会反，03 的时间线跟着错。

## §2 核心结构体

每个结构体：
- 字段表（字段 / 类型 / 语义 / 可选值）
- flags 子表（位 / 名称 / 含义 / 谁设置）
- 代码示例（真实初始化序列）

## §3 结构关系 ASCII 图

- 必须有一张"本模块总线 ↔ platform 总线"的图
- 图中标注 `dev.parent` 缝合点（哪一行赋值）

## §3b ★ 内存布局图（当结构体是跨边界/跨主体共享的内存时必写）

普通结构关系图画的是**指针**；共享内存要画的是**字节排布**。适用对象：vring（virtio）、
scatterlist、skb、dma-buf、ringbuffer 类。四件事一个都不能省：

```
偏移      字段                    宽度   字节序     谁写      谁读
0x00      desc[0].addr            8B     LE(modern) 驱动侧    对端
...       avail->idx              2B     LE(modern) 驱动侧    对端
...       used->idx               2B     LE(modern) 对端      驱动侧
          ^^^ 对齐要求 / 是否要求物理连续 / 谁负责 DMA 映射
```

- ★ **"谁写谁读"必须逐字段标**——共享内存两侧都会写，只标结构体级别等于没标
- ★ **字节序逐字段标**，别写在段落里。跨边界结构体的字段表要多一列「字节序」
- 对齐/连续性/映射责任写在图下，不要混进字段表

## §4 传输数据流图

从调用者到硬件的数据路径：
```
调用者 API → 消息构造 → 队列提交 → 控制器回调 → 硬件
```
每一步标出关键函数和文件:行号。

## §5 全局变量与锁

- 全局变量表（变量 / 类型 / 保护锁 / 初始化时机）
- 锁顺序说明（如果有多把锁）

## §6 命名约定速查

- 函数命名前缀规律（如 `spi_` / `spi_controller_` / `spi_mem_`）
- 宏命名前缀规律（如 `SPI_` / `SPI_CONTROLLER_` / `SPI_MEM_`）
- 结构体命名约定

## §7 内部结构表

核心 .c 里的非导出结构体（如 i2c 的 `i2c_adapter_dev`、spi 的 `spi_controller_dev` 变体），
读者从 .h 看不到但影响行为。

## 常见陷阱

- 把 controller 当 platform_device 的子集（它通过 dev.parent 缝合，不是继承）
- 把 bus_type 的 match 函数当万能匹配（它只做 driver/device 绑定，不做探测）
- 忘记 `dev.parent` 决定了设备层级/sysfs 挂载位置
- ★ 共享内存结构体只画了指针关系，没画字节排布（读者无法判断对端看到的是什么）
- ★ 把双层可插拔画成单层（传输层 ops 和设备驱动 ops 混成一张图，调用方向会反）
