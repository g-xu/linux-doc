## 主题选择

- 主题数下限 ≥6（如果子系统有足够难的概念）
- 选题标准：子系统里最难理解/最重要的概念
- **必选一类**：这个子系统里**最容易被类比错的那组关系**。判据是"用设备模型的 device↔driver 去套会套错的地方"。i2c 的两道是：
  - `i2c_adapter` 和 `i2c_algorithm` 是什么关系？（答案是容器↔操作表，等同 `file_operations`，**不是** device↔driver）
  - `i2c_adapter` 为什么注册在 `i2c_bus_type` 上而不是 platform 总线上？（控制器的双重身份：对 SoC 是 platform 设备，对芯片是总线接口）

  换到别的子系统就换成对应的那组：spi 是 `spi_controller`↔`spi_master` 命名史，clk 是 `clk`↔`clk_hw`↔`clk_core` 三层，pinctrl 是 `pinctrl_dev`↔`pinctrl_state`。
- 其余候选清单（可参考）：
  - 队列机制：为什么 message 要排队而不是直接发硬件？
  - 用户态路径：从 ioctl 到硬件经过几层？
  - 抽象层：为什么某子框架的抽象比通用路径更高效？
  - 锁机制：核心那把锁为什么需要？为什么是这个锁类型？
  - 错误恢复：操作失败后控制器怎么恢复？
  - 一对"名字很像但语义不同"的 API（读者最容易踩，如 `i2c_lock_addr` ↔ `i2c_check_addr_busy`）

## 每个概念四段式

1. **问题标题**：只写要说明的问题，不要夹带类比
2. **先举个例子**：用日常生活类比引入，可以多说几句。**选材三条标准 + i2c 八主题类比库见 `methodology.md` §E**
3. **回到代码**：给出关键源码行号，文件路径写全，不能裸 `:N`
4. **这个类比什么时候会误导你？**：明确类比和代码之间的真实差异。写法：顺着类比往下推，**第一个推错的结论是什么**——那句话就是本段内容。推不出来说明类比太泛，换一个

## 常见陷阱

- 标题里夹带类比（应该只在正文"先举个例子"里用）
- 类比后面没有源码行号（不能只讲故事）
- "类比边界"段泛泛而谈（必须指出一个真实的技术差异）
- 主题数太少（<6 个说明对子系统理解不够深）
