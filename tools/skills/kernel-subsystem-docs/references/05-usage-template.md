## 篇首

- 声明"骨架未编译"——别把免责声明只放在 99
- 枚举本子系统有哪些角色，每个角色一节，不能漏

## 角色枚举

列出本子系统的全部角色（如 device driver / controller driver / slave / 用户态），
每个角色一节。列了但没写的角色不算——必须有一节。

## 每个角色的固定子节

1. **注册/探测骨架**：最小可编译的代码模板
2. **probe 迁移**：旧 API → 新 API 的迁移要点（如果有）
3. **remove 返回值**：remove 回调该返回什么、返回非零会怎样
4. **PM 回调**：runtime suspend/resume 骨架（如果有）
5. **API 快速参考**：本角色最常用的 5-10 个 API（三列表）

## 用户态角色

- 深度下限：至少覆盖 open → ioctl → close 的完整路径
- 每个 ioctl 给出输入/输出结构体
- 错误处理示例

## ★ 独立一节：近邻符号区分（强制，不能散在各节陷阱表里）

标题写成 `§N 近邻符号区分：名字很像，行为不一样`，放在"相关章节"之前。
**一组一小节**，每小节四件事：两个（或多个）符号的定位 → 真实区别 → 判据 → **错用会怎样**。

散在各节的陷阱表等于没有入口——读者要先知道有坑才找得到。这一节是那个入口。

选组的六个来源（spi 实例，换子系统时按同样的类别去找）：

| 类别 | spi 实例 | 为什么危险 |
|---|---|---|
| 同一动作的同步/异步/加锁三态 | `spi_async` / `spi_sync` / `spi_sync_locked` | 上下文要求不同（"可睡眠" vs "irq 里也能调"） |
| 成对回调的两层 finalize | `spi_finalize_current_transfer` / `..._message` | ★★ 调错一层直接挂死，助记："你实现了哪一层，就调另一层的 finalize" |
| 只差字节序的便捷读写 | `spi_w8r16` / `spi_w8r16be` | 差两个字母，一个不转换一个转换，**在对称数值上不暴露** |
| 只差一个字母的取值函数 | `spi_get_drvdata` / `spi_controller_get_devdata` | drvdata vs devdata |
| 同名标志在不同对象上 | `SPI_NO_TX`（`spi->mode`）/ `SPI_CONTROLLER_NO_TX`（`ctlr->flags`） | 不是新旧名，是两件事 |
| 改名期的双名字段 | `->slave` / `->target`（`union` 同址） | 四种机制形式，只有两种真是"一份代码" |

一定要写进这一节的还有：**有完整 kerneldoc 却不导出的内部函数**（它长得最像公开 API）。

## 符号验证

正文出现的每个内核函数名/宏名/标志名/内核打印字符串，
都跑一次全树 grep 确认本版本存在。空结果 = 幻觉。

两条判据别混：

- **存在** = grep 有命中。注意 tab 陷阱，`#define` 与宏名之间常是 TAB：
  用 `grep -nE "define[[:space:]]+FOO"`，别用 `grep "define FOO"`
- **读者能用** = `EXPORT_SYMBOL*` **且**头文件里有声明。★ **不是"有没有 kerneldoc"**——
  写满 kerneldoc 的 `static` 内部函数比没注释的更危险

## 常见陷阱

- 角色列了没写（枚举表里有，正文没有对应章节）
- 用户态太浅（只列 ioctl 名不给参数结构体）
- 骨架代码引用了不存在的符号（必须全树 grep）
- 交叉引用陈旧（"见 0X §Y" 指向的章节号已变）
- **近邻符号只在各节陷阱表里顺手提了一句**，没有独立一节承载（读者找不到入口）
- **把"有 kerneldoc"当成"是公开 API"**（判据是导出 + 头文件声明）
- **写"X 是 Y 的别名"而没打开定义**（四种机制里有两种会分叉）
- **同一条跨篇引用在篇首和篇末表里各写一遍，只改了一处**——改一条引用要 `grep` 整篇
